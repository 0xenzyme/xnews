# AI每日精选（2026-11-16）

周日档，没有大模型发布，开发者圈的热点集中在 agent 工具本身：Claude Code 推出实验性 Code Mode，让模型写一段 JavaScript 批量调用工具；同期 OpenAI Codex 仓库的一条 GitHub Actions 漏洞链被公开，展示了 prompt injection 如何一路打到 npm 发布权限。评测侧，Artificial Analysis 的 Coding Agent Index 出现 Fable 5.2 与 Opus 5.5 并列第一，「拉满思考档」反而掉分。产业侧，英伟达被 WSJ 曝出东南亚数据中心转运约 120 亿美元芯片的记录，FT 又报黄仁勋在考虑回归。

## 1. Agent 与开发工具

### Claude Code 上线实验性 Code Mode：一段 JS 代替一连串工具调用

- 发生了什么：Claude Code v2.1.323 起提供实验性 Code Mode，默认关闭，需要设置环境变量 `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`。开启后 Claude 不再一次调一个 Bash / Read / Edit 并逐个读结果，而是写一段 JavaScript 在会话里执行：可并行跑命令、把上一步结果喂给下一步，只把需要的输出交回模型。官方文档说明每个由代码发起的工具调用仍会经过 deny / ask 权限规则和 PreToolUse hook；不支持经网关、Bedrock 或 Google Cloud 等第三方渠道使用。@RhysSullivan 拆了实现：Claude Code 用 Bun 内的 node:vm 进程内运行，对比 Codex 用 V8、OpenCode 用自写解释器、Pi 用 QuickJS。
- 为什么值得关注：「agent 太啰嗦」的解法从更长上下文转向批处理和代码编排，和上期 Google Antigravity 的 Dynamic Workflows 是同一方向。
- 原帖与互动：[pggalaviz](https://x.com/pggalaviz/status/2121652838447169783)｜约 10 万曝光、328 赞；[RhysSullivan（实现对比）](https://x.com/RhysSullivan/status/2121787604215664891)｜约 5.2 万曝光、720 赞；[Voxyz_ai（官方指南解读）](https://x.com/Voxyz_ai/status/2121951349718053297)｜约 1.1 万曝光；官方文档 [code.claude.com/docs/en/code-mode](https://code.claude.com/docs/en/code-mode)
- 核验：功能、版本号、开关方式与权限行为 verified（官方文档）。广为流传的「省 37% token、会话长 1.6 倍」在官方 Code Mode 文档里查不到；中文作者 [lzuren2001](https://x.com/lzuren2001/status/2121835811411050581) 指出 37% 来自 Anthropic 早先一篇 API 功能文章，本期按 unverified 处理。实现细节为第三方逆向，author-claim。
- 判断：多文件改动、批量检索这类「工具调用密集」的任务值得开来试；别把额度节省当成既定事实，自己对比一次用量再决定是否默认开启。

### Codex 仓库 issue 标注流水线被 prompt injection 打穿，可一路拿到 npm 发布权限（已修复）

- 发生了什么：安全公司 Depi 11/11 披露：openai/codex 的 issue 自动打标签工作流把任何人提交的 issue 标题和正文直接塞进 Codex agent 的提示词，攻击者可借此在 agent 沙箱内执行命令，再串联 runner 令牌、缓存投毒和高权限工作流，理论上能控制 @openai/codex 的 npm 发布。OpenAI 已把这一步改成关闭工具、严格校验 JSON 的 Responses API 调用。周末这条在 X 上被重新转开；另有用户称 Codex 0.168 的 `codex exec --sandbox workspace-write` 会在未信任仓库里把 MCP server 跑在沙箱外，0.169 已修。
- 为什么值得关注：继上期 Cursor 事件之后，又一个「AI 编码工具自身供应链」案例。只要 CI 里的 agent 会读外部文本、又有写权限，就可能被利用。
- 原帖与互动：[SaifuddinAmri__](https://x.com/SaifuddinAmri__/status/2121835397454123386)｜约 300 曝光；[thomas_rehmer](https://x.com/thomas_rehmer/status/2122052922372411395)；[theomlondhe（0.168 沙箱问题）](https://x.com/theomlondhe/status/2121969004067577913)；披露原文 [depi.security](https://depi.security/blog/20261111-backdooring-codex/)；修复提交 [openai/codex@14e0399](https://github.com/openai/codex/commit/14e0399)
- 核验：披露与修复提交存在 verified（经网页检索确认标题与提交信息，未逐行复现攻击链）。攻击链的可达性为 Depi 自述，author-claim。0.168 沙箱问题为单个用户报告，unverified。X 上热度很低，入选是因为对开发者的实际影响。
- 判断：检查自家仓库里「LLM 读 issue / PR 文本」的 Action：关工具、限权限、输出做结构化校验。用 Codex CLI 的升到 0.169 以上。

## 2. 模型与评测

### Coding Agent Index v2.1：Fable 5.2 与 Opus 5.5 并列 58 分，「max」档因超时反而更低；Teknium 劝 Luna 用户换 DeepSeek

- 发生了什么：多位用户转述 Artificial Analysis 11/14 更新的 Coding Agent Index v2.1（由 FrontierCode-AA 2.0、Terminal-Bench 4.1、SWE-Atlas-QnA-AA 组成）：Anthropic 的 Fable 5.2 与 Opus 5.5 并列 58；Fable 5.2 在 max 档只有 56，原因是 16% 的 FrontierCode 尝试撞上时间上限（xhigh 档为 1%），超时按零分计。另一边，Nous Research 的 @Teknium 在 Hermes Agent 实测后发 PSA：用 OpenAI Luna 的不如换 DeepSeek Flash 或 Terra，同价更准；他还称 Kimi 成本接近 Opus 5.5 而准确率更低。
- 为什么值得关注：评测开始把「时间上限」和「每任务成本」算进分数，思考档位越高越好的直觉不再成立；Fable 5.2 在 Claude Pro 的免费周也将结束，开发者要在 Fable 和 Opus 之间做价格取舍。
- 原帖与互动：[aapakari](https://x.com/aapakari/status/2122092471920259089)｜约 400 曝光；[rfanazhari（max 档超时）](https://x.com/rfanazhari/status/2121792224253956231)；[Aryan_Ali_Pro（指数构成）](https://x.com/Aryan_Ali_Pro/status/2122030816645583080)；[Teknium](https://x.com/Teknium/status/2121881702247387455)｜约 4.4 万曝光、1,203 赞；[Teknium（Kimi）](https://x.com/Teknium/status/2121881891594989978)｜约 7,100 曝光

- 判断：跑长任务的 agent 别默认拉满思考档，先看任务时限内的完成率。

### Gemini 4 Carbon 在低思考档把整页草稿推理吐给用户，随后自我「刹车」

- 发生了什么：数学家 Alon Amit 用 Gemini 4 Carbon 问数学题，思考档位误设为 Low，模型先输出约六屏推导，随后出现「我是不是在直接写给用户？」「停，好，停下来喘口气」之类的自我纠正，持续数页。截图在 X 上广泛传播。
- 为什么值得关注：低思考档本意是省 token，但思考块提前关闭会把内部草稿直接暴露给终端用户，在产品里会是体验和合规问题。
- 原帖与互动：[alonamit](https://x.com/alonamit/status/2121751642005721122)｜约 38.8 万曝光、4,841 赞
- 核验：单一用户截图，author-claim；Google 未回应。
- 判断：接入 Carbon 的产品如果暴露「思考档位」给用户，建议在服务端兜底过滤异常长输出。
