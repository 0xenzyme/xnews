## 4. Agent 与开发工具

### Claude Code 团队讲「验证」：约 90% 代码由 Claude 写和审；Linear：53% 的 PR 只经作者 + agent 评审

- 发生了什么：claude.dev 博客（Addy Osmani 署名）介绍 Claude Code 团队约 90% 代码由 Claude 编写和评审，靠端到端、属性测试和差分测试让 agent 带证据验证自己的工作；有了验证闭环才能并行跑几十上百个 Claude。Linear 发布代码评审数据：1 月几乎每个 PR 都有第二位人类评审，到 10 月 53% 只由作者和 agent 评审；Linear 工程师补充回滚与 bug 率反而下降。同期「理解债」（代码写得比人理解得快）话题在 X 上发酵。
- 为什么值得关注：两家一线团队给出了同一个答案：把人的注意力放在验证机制和高风险改动上，而不是逐行看 diff。
- 原帖与互动：[ClaudeDevs](https://x.com/ClaudeDevs/status/2122457608963395586)｜约 16 万曝光、3,672 赞；[linear](https://x.com/linear/status/2122374415446880512)｜约 2 万曝光；[dizaytsev（回滚下降）](https://x.com/dizaytsev/status/2122405549837082955)；[Prayag12B（理解债）](https://x.com/Prayag12B/status/2122350982705119490)｜约 6.7 万曝光；原文 [claude.dev 博客](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/)、[linear.app/data/code-review](https://linear.app/data/code-review)
- 核验：两篇原文 verified；「回滚与 bug 率下降」为 Linear 工程师个人说法，author-claim。
- 判断：最可直接抄的一条：每个仓库写一个能启动并跑通应用的 verify 脚本 / skill，提交前让 agent 自己跑。
