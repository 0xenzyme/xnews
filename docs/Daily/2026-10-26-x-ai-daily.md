## 2. Agent 架构与用量

### Anthropic：建议拆掉多余 subagent，折回主循环 + skills

- 发生了什么：Anthropic Applied AI 指南（claude.com）建议企业去掉不必要的 subagent——把专长写成 on-demand skills、把动作暴露为 tools/MCP，仅在并行、隔离上下文或单 agent 吃力时再拆。病毒帖 @cherry_mx_reds 摘要：单 agent + skills 常胜过复杂多智能体；一客户拆掉后运行约 2× 更快。规则口诀：Skills = HOW；Tools/MCP = DO；Subagents = 并行/隔离。随 Opus 5.5 等更强模型，「能加什么」让位给「能删什么」。
- 为什么值得关注：过去一年 org-chart 式多智能体默认被官方改写——延迟、token 与验证断层多出在 handoff。
- 原帖与互动：[cherry_mx_reds](https://x.com/cherry_mx_reds/status/2113969070118666670)｜约 83.0 万浏览、3401 赞、229 转发、204 引用。指南：https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop

- 判断：先做 eval——把现有 subagent 指令改成 skill、动作改成 tool，看质量是否持平再删。

### Naive RAG 仍强：复杂 agentic memory 未必必要

- 发生了什么：论文 *Is Complex Agentic Memory Always Needed? Naive RAG Is Stronger Than We Thought*（arXiv:2610.30755，HF papers）提出 Raw-RAG——对原始对话历史做稠密检索 + rerank 再交给 reader LLM。在 LoCoMo / LongMemEval / MEME / MemoryAgentBench 等设置中，Raw-RAG 在七组对照里六组排名第一，相对最强 agentic memory 基线高出约 0.13–5.53 分；作者认为更高证据覆盖可弥补利用率劣势，复杂变异/结构化记忆并非总是必要，naive RAG 应成必跑基线。
- 为什么值得关注：和 Anthropic「折回主循环」同向——又一次「删复杂性」证据，打在 memory 子系统而非 org-chart agent。
- 原帖与互动：https://huggingface.co/papers/2610.30755 ｜ https://arxiv.org/abs/2610.30755｜无 X metrics。
- 核验：verified — arXiv/HF 论文页；分数为论文自评（author-claim 于复现前）。
- 判断：上线 fancy memory 前先钉死 Raw-RAG 基线；若打不过再谈 mutation / 结构化存储。

### IQuest-Q1：320B/15B MoE 的 agentic CLI 基础模型（开源声明）

- 发生了什么：*IQuest-Q1: Advancing Foundation Capabilities for Agentic CLI Systems*（arXiv:2610.30949）介绍稀疏 MoE 共 320B（激活约 15B）的 agentic 基础模型，三阶段：稳定预训练（Stable SplitNorm / Muon / muP + 提高 coding 配比）→ 细粒度 mid-training 扩域与上下文 → 多 scaffold / 多版本后训练（SFT + 领域 RL + MOPD）再做 model merging；作者声明开源以支持社区研究。
- 为什么值得关注：CLI / coding agent 底座又多一块大 MoE 候选——需对照权重是否已落地、与 Nanbeige 教师档/Qwen 同台评测。

- 核验：author-claim — 论文自述与「将开源」声明；权重可用性与独立基准待核对。
- 判断：先盯发布渠道与 harness 评测，再决定是否纳入本地/蒸馏候选池。
