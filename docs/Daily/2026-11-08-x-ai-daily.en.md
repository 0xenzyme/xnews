## 1. Agent memory

### Anthropic: the components of agent memory, and "dreaming"

- What happened: On Nov 6 @AnthropicAI published [The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory). In session, Claude judges what's worth noting; between sessions, "dreaming" replays raw transcripts to fix wrong notes, build wiki-style representations, and promote a small set of notes into the layer preloaded every session. Reported numbers: on ~350k internal files (~420M tokens), scaling dreaming from 2 to 128 sessions lifted wiki-only scores from 13% to 48%; search plus wiki went 54% to 61% (search alone 53%) and saved ~20k tokens per question; rewriting the wiki-build instructions raised contract-fact retention from 41/57 to 57/57. For strong models, telling Claude what memory is for beat prescribing how to use it; a fixed "record only failures" rule cut the gain.
- Why it matters: A copyable layering for long-running agents: notes in session, offline verification, and a tiny top layer (Claude Code preloads only the first 200 lines / 25 KB of `MEMORY.md`).
- Source & engagement: [AnthropicAI](https://x.com/AnthropicAI/status/2118814753154064501), ~1.54M impressions, 12,157 likes, 1,082 reposts, 691 quotes, 873 replies, 10,881 bookmarks (most-bookmarked post in this window).
- Verification: verified, official blog plus official X; all figures are Anthropic internal evals.
- Take: "Dreaming is offline memory cleanup" is fair; "Claude now learns continuously / updates weights" is not, and the post explicitly excludes weight changes.

## 4. AI-assisted cryptanalysis

### Google DeepMind: AI agents find two weaknesses in legacy RSA-1024

- What happened: On Nov 6 @GoogleDeepMind shared research, written up by Pushmeet Kohli: with human supervision, AI agents found (1) once an attacker controls roughly half the signed block, padding adds no protection; a sandboxed reproduction on an already-broken 1024-bit benchmark key used 3.5x less CPU time, and a new algorithm for the short-fingerprint case is estimated at ~1,600x faster than the prior best; (2) a batch-factoring algorithm that cuts the average cost of each additional 1024-bit key by ~30x vs earlier batch methods. Collaborators include Nadia Heninger (UCSD/Inria) and Emmanuel Thomé (Inria). DeepMind says 2048-bit and larger keys stay secure.
- Why it matters: A concrete "AI speeds up math and security research" result, and a nudge for anything still on 1024-bit RSA.
- Source & engagement: [GoogleDeepMind](https://x.com/GoogleDeepMind/status/2118755418675765656), ~120k impressions, 1,365 likes, 182 reposts, 371 bookmarks; [pushmeet article](https://x.com/pushmeet/status/2118752095859794390), ~130k impressions.
- Verification: verified, official X plus DeepMind technical papers; the 1,600x figure is a theoretical estimate.
- Take: "AI lowered attack costs on obsolete RSA-1024." Not "RSA is broken."
