## 1. Agents & dev tools

### Claude Code ships experimental Code Mode: one JS snippet instead of a chain of tool calls

- What happened: From Claude Code v2.1.323 there is an experimental, off-by-default Code Mode, enabled with `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`. Instead of calling Bash / Read / Edit one at a time and reading each result, Claude writes JavaScript that runs in the session: commands can run in parallel, results feed the next call, and only the needed output goes back to the model. The docs say every tool call made from code still passes through deny/ask permission rules and PreToolUse hooks; it isn't available via gateways, Bedrock or Google Cloud. @RhysSullivan compared implementations: Claude Code uses node:vm in-process under Bun, Codex uses V8, OpenCode a custom interpreter, Pi QuickJS.
- Why it matters: The fix for chatty agents is moving toward batching and code orchestration rather than longer context — the same direction as Google Antigravity's Dynamic Workflows last edition.
- Source & engagement: [pggalaviz](https://x.com/pggalaviz/status/2121652838447169783) | ~100K views, 328 likes; [RhysSullivan (implementation comparison)](https://x.com/RhysSullivan/status/2121787604215664891) | ~52K views, 720 likes; [Voxyz_ai (guide walkthrough)](https://x.com/Voxyz_ai/status/2121951349718053297) | ~11K views; docs [code.claude.com/docs/en/code-mode](https://code.claude.com/docs/en/code-mode)
- Verification: Feature, version, flag and permission behavior verified (official docs). The widely shared "37% fewer tokens, 1.6x longer sessions" does not appear in the Code Mode docs; Chinese-language writer [lzuren2001](https://x.com/lzuren2001/status/2121835811411050581) traces 37% to an older Anthropic API article — treated as unverified. Implementation details are third-party reverse-engineering, author-claim.
- Take: Worth trying for tool-heavy work (multi-file edits, bulk search). Measure your own usage before assuming quota savings.

### Codex repo's issue-labeler workflow was prompt-injectable all the way to npm publishing (fixed)

- What happened: Security firm Depi disclosed on 11/11 that openai/codex's issue-labeling workflow fed any issue's title and body straight into a Codex agent prompt, allowing command execution in the agent sandbox; chained with runner tokens, cache poisoning and privileged workflows, it could in principle control @openai/codex npm publishing. OpenAI replaced the step with a Responses API call with tools disabled and strict JSON validation. The story recirculated on X this weekend. Separately, a user reports that Codex 0.168's `codex exec --sandbox workspace-write` started an untrusted repo's MCP server outside the sandbox, fixed in 0.169.
- Why it matters: After last edition's Cursor incident, another supply-chain case inside an AI coding tool. Any CI agent that reads outside text and holds write permissions is a target.
- Source & engagement: [SaifuddinAmri__](https://x.com/SaifuddinAmri__/status/2121835397454123386) | ~300 views; [thomas_rehmer](https://x.com/thomas_rehmer/status/2122052922372411395); [theomlondhe (0.168 sandbox issue)](https://x.com/theomlondhe/status/2121969004067577913); disclosure [depi.security](https://depi.security/blog/20261111-backdooring-codex/); fix [openai/codex@14e0399](https://github.com/openai/codex/commit/14e0399)
- Verification: Disclosure and fix commit exist, verified (confirmed via web search titles/commit message; chain not reproduced). Reachability of the full chain is Depi's claim, author-claim. The 0.168 sandbox report is a single user, unverified. Low X engagement; included for practical impact.
- Take: Audit any Action where an LLM reads issue/PR text: disable tools, scope tokens, validate structured output. Upgrade Codex CLI to 0.169+.

### Gemini 4 Carbon on Low thinking dumped pages of scratchpad to the user, then "braked" itself

- What happened: Mathematician Alon Amit asked Gemini 4 Carbon a math question with Thinking left on Low; it emitted about six screens of derivation, then self-corrections along the lines of "am I writing directly to the user?" and "stop, okay stop and breathe," for pages.
